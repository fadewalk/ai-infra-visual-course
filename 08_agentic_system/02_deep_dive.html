Agent 深水区一页通

第 9 课讲了 Agent 的骨架（LLM+工具+循环）。这一页把四块深水区压成速览：12-Factor 工程原则、记忆系统、多智能体编排、上下文工程——每块带上游深读入口。

一、12-Factor Agents：把 Agent 当分布式系统建

开源圈的共识：Agent 工程的问题，八成是分布式系统的老问题换了皮肤。12 条原则里，对 SRE 最亲切的五条：

owns 控制流：别把循环完全交给框架黑盒，自己 owns while 循环🧠 类比：用框架可以，控制平面要在自己手里
状态外置：会话状态存外部（可恢复），别塞在进程内存🧠 类比：无状态服务 + 外置存储
工具就是接口：工具定义=API 契约，写清楚输入输出与副作用🧠 类比：OpenAPI 规范
可恢复性：任意一步崩溃后能从断点重放🧠 类比：checkpoint / 幂等重试
接触原始上下文：别让框架过度包装历史，可观测可调试🧠 类比：要看得见原始日志，不要只看仪表盘

完整 12 条见上游 12-Factor Agents 介绍。

二、记忆系统：内存 vs 外存的老问题

层级载体特点代表
短期记忆上下文窗口快、贵、会话结束即失对话历史本身
长期记忆向量库 / 图数据库持久、可检索、要管理生命周期Mem0、MemoryOS 分层设计
经验记忆轨迹库存"过去怎么解决的"，RAG 回来复用Agent 经验复用类系统

🧠 一句话：就是计算机存储层级（寄存器/内存/磁盘）的 Agent 版。上游有 记忆系统架构总览 与 MemoryOS/Mem0 逐个拆解。

三、多智能体：什么时候值得"多开"

自测：你的任务需要多智能体吗？（勾选符合项）
任务能自然拆成视角不同的子角色（如：实现者 vs 评审者）
子任务间上下文需要隔离（一方的大量中间产物会污染另一方）
需要并行处理（多路检索/多方案同时试）
有明确的裁决者设计（谁汇总、谁拍板）

经验法则：只是为了"显得智能"而多开，通常不如一个长上下文单 Agent + 好工具。上游有 多智能体理论 与 LangGraph 企业级实战。

四、上下文工程：窗口是贵资源

四大策略

写（重要结论落盘到外部）、选（只检索相关片段进窗口）、压（历史摘要压缩）、隔离（子任务各开独立上下文）。

🧠 类比：缓存的写策略 + 淘汰策略 + 分区。

与推理系统的合流

上下文工程的每一个决策，最终都反映为 KV Cache 的命中率和显存账（第 3 课）——Agent 负载正在重塑推理系统设计。
