Agent 是怎么回事？

给大模型配上"工具"和"循环"，它就从"只会说"变成"会自己动手干"。下面这个 Agent 正在替值班 SRE 查一台 GPU 节点的故障——点步进看它怎么思考。

一、动手：看一个运维 Agent 干活

📋 任务：「gpu-03 这台节点上有个训练作业一直重试，帮我查一下原因并给出处理建议。」
🤔 思考 Thought→ ⚡ 行动 Action→ 👁 观察 Observation→ 循环…直到能回答

二、Agent = LLM + 工具 + 循环

LLM 是大脑

负责理解任务、拆解步骤、决定"下一步干什么"——就是上面每一步的"思考"。

🧠 决策引擎，不是执行者。

工具是手脚

搜索、查库、执行命令、调 API……模型输出"调用哪个工具+参数"，系统替它执行并把结果喂回来。

🧠 类比：Runbook 里能自动执行的动作。

循环是灵魂

思考→行动→观察→再思考……直到任务完成。没有循环就只是单轮问答。

🧠 这个循环叫 ReAct（Reason + Act）

三、关键词卡

Function Calling 工具调用

模型按约定格式输出"要调用的函数名和参数"，由外部系统真正执行。

🧠 类比：模型填工单，人来执行工单——只是执行者也是程序。

MCP

Model Context Protocol——工具接入的开放协议，一次接入、多家模型/客户端通用。

🧠 类比：USB-C——以前每个设备一种线，现在一个口全搞定。

上下文工程

窗口有限，放什么进上下文要精心管理：历史压缩、关键信息前置、工具结果裁剪。

🧠 类比：容量规划——贵资源只放热数据。Agent 越跑越长，这越关键。

记忆系统

短期记忆 = 上下文窗口；长期记忆 = 外挂数据库（向量库/图库），用时检索回来。

🧠 类比：内存 vs 外存，照搬计算机存储层级。

四、和你的关系：AIOps 正在变成现实

运维 Agent 已在落地

K8s 运维智能体（如 Kagent）、告警自动分诊、故障初诊报告……上游仓库有专门的 Kagent 拆解文章。

🧠 你现在写的 Runbook，就是未来运维 Agent 的"技能书"。

边界要清醒

Agent 会出错、会被上下文长度限制、执行高危命令需要审批闸门。"能自动"≠"该全自动"——分级放权是 SRE 的老本领。

🧠 类比：自动化变更也要分只读/低危/高危审批。
